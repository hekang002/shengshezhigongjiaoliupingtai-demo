# 湖北供销·心声管理端原型

管理工作台原型位于职工端工程内，不单独承载登录页。用户从职工端唯一登录页的“管理视图”入口进入；两端在同一域名和端口下共享演示业务数据。

## 运行

在上一级 `原型优化设计` 目录启动静态服务：

```bash
python3 -m http.server 4177
```

浏览器访问 `http://127.0.0.1:4177/`，点击“管理视图”进入管理端。管理端直接地址为 `http://127.0.0.1:4177/管理端原型设计/`，请勿单独启动管理端目录的服务，否则无法共享职工端数据。

## 已覆盖页面

- 管理端入口：由职工端登录页的“管理视图”角色入口跳转
- 运营工作台：指标卡、风险提示、优先处理队列、近期动态
- 溯源查询：与审核管理平级，仅查看本人申请；通过帖子编号定位有账号绑定的匿名内容，提交具体事由。批准后仅本申请人可在 24 小时内查看一次姓名和部门，查看动作单独记入审计日志。
- 溯源查询审核：位于审核管理的用户审核之后，由非申请人的审核人员处理；无可核实身份绑定的内容不得批准。批准仅授权本帖、姓名和部门，超期或用尽次数后不可再查。
- 审核管理：平台管理员包含信息内容审核、评论审核、举报复核、用户审核和溯源查询审核；内容管理员可访问信息内容审核、评论审核、举报复核和溯源查询审核
- 内容管理：包含信息台账管理、通知公告管理、政策与问答、轮播图管理、回音壁发布五个页面
- 内容管理 Mock 数据：信息台账、通知公告、轮播图、回音壁发布各不少于 20 条；政策与问答共 20 条（政策 10 条、问答 10 条），现有浏览器数据采用增量补齐，不覆盖人工操作记录
- 轮播图管理：上传 JPG/PNG/WebP 图片（不超过 1 MB），配置标题、副标题、显示顺序与启停状态；跳转可关联信息台账中的已发布帖子及回音壁、已发布公告、政策和问答，或使用 HTTPS 外链。职工首页展示启用记录，关联内容下架后自动跳过。
- 信息台账管理：收录私密发布和公开发布成功的帖子，敏感内容待审核、退回修改和已驳回记录统一留在信息内容审核；按全部、建言献策、心声诉求、业务交流、回音壁分类查询；职工帖子支持编辑、启用/禁用和删除，已关联办理事项的帖子禁止删除；回音壁仅展示管理端公开发布记录
- 信息台账管理：列表以互动数据列展示浏览 PV、点赞、评论、收藏、分享；帖子详情包含内容信息、互动分析、评论明细、操作记录四个页签
- 互动数据口径：浏览同时记录 PV/UV，互动率按（点赞 + 已发布评论 + 收藏 + 分享）/ UV 计算；点赞和收藏保留用户级行为记录，分享只记录入口和次数，不记录接收人
- 互动明细权限：平台管理员可查看点赞/收藏用户记录，内容管理员仅查看汇总；匿名作者身份仍需独立匿名溯源权限和理由登记
- 信息内容审核：审核建言献策、心声诉求和业务交流，支持全部、建言献策、心声诉求、业务交流四个 Tab；审核队列为待审核、风险待审、已处理，系统风险预警仅供参考，最终由审核人员判断；其中前两类通过后进入事项分办，支持通过、退回、驳回、隐藏和恢复
- 建言献策与心声诉求：职工提交后默认为“私密发布”，仅作者和审核人员可见；审核人员选择“公开发布”后才进入职工端公共信息流，信息台账同时保留私密与公开记录
- 评论审核：独立审核评论；通过后在职工端展示
- 举报复核：核对来源帖子与举报原因，填写复核意见并判定成立或不成立；不自动隐藏帖子
- 通知公告管理：公告一次性发布，不提供撤回或重新发布；列表记录应发布人数、发布成功数和成功率，支持编辑标题与正文、二次确认删除，并同步职工端通知公告
- 政策与问答：发布政策解读、回答职工提问，已发布内容同步职工端“政策答疑与公开”
- 政策发布：发布后不提供撤回且不显示状态列，支持编辑政策内容和二次确认删除；编辑保留原发布时间，删除后同步从职工端移除
- 回音壁发布：通过“新增发布”从信息台账选择已公开帖子，编辑公开标题、内容和范围后发布；发布记录支持查看、编辑、删除，不提供撤回状态
- 事项分办：待分办、已分办、答复审核三个 Tab；待分办支持事项登记、主办/协办、复杂度、反馈方式，已分办跟踪责任人和办理状态，答复审核承接承办人提交的待复核答复
- 办理管理：进度、临期风险、催办、事项详情时间线
- 承办管理：平台管理员与承办负责人共用承办工作台、待办筛选、事项办理、答复草稿、催办提醒、已公开答复和部门统计；承办账号通过职工端唯一登录页进入，本部门事项按主办部门和当前承办人筛选
- 承办办理与转办：建言献策、心声诉求不因敏感词命中而退出办理；内容审核通过并完成分办后直接进入承办待办；承办人负责进度、材料和答复，必要时可发起转办，管理端负责转办管控、答复复核和办结归档
- 平台管理员在“审核管理”下处理信息内容审核，在“事项办理”下查看事项分办和公开与归档；事项分办内部通过待分办、已分办、答复审核三个 Tab 完成流转；承办角色在“承办管理”下使用工作台、办理反馈、草稿与通知和已办事项
- 用户审核：平台管理员查看待审核、已通过和已驳回申请；驳回填写原因，审核结果同步职工端
- 左侧点击式抽屉：所有角色默认只展示一级菜单；点击一级展开二级页面，切换一级时自动收起上一组
- 系统设置：位于平台管理员菜单末尾，依次为用户管理、组织架构、角色管理、菜单管理、字典管理、系统日志
- 配置管理：维护职工发帖栏目（新增、改名、排序、启停）及敏感词库（新增、编辑、适用范围、启停）
- 流程配置原型：五套按提交事件区分的模板列表和节点编辑画布，支持节点增删、条件分支、角色与超时配置、路径检查、模拟、保存草稿及发布新版本。配置作为独立演示数据保存，尚未接管现有职工端提交和管理端审核运行逻辑；具体目标规则见《流程配置业务需求》。
- 基础配置：位于平台管理员“配置管理 → 流程配置”之后，演示配置密码策略、会话时限和登录失败锁定；参数保存在浏览器演示数据并记入操作日志，不影响真实登录与会话校验。
- 组织架构：区域/机构筛选、父子层级展开、同级排序、显示/状态、组织增改与下级新增；仅允许删除未被事项或用户引用的末级组织
- 用户管理：按组织树与账号/姓名/手机号筛选，维护用户组织和状态；支持按当前筛选范围导出 CSV、下载模板并批量导入用户，新用户仅是原型档案，不自动生成登录凭据
- 角色管理：五种内置演示角色及自定义角色；新增/编辑采用基础信息与菜单权限树的一体化弹窗，支持节点关联、节点独立、收起展开及已选统计；“数据权限”独立配置全部、自定义、本部门、本部门及以下、仅本人等范围；“分配”通过用户表格搜索、勾选、全选来加入或移除角色用户，但这些原型配置不改变运行时鉴权
- 菜单管理：树形目录、状态与显隐、增改下级、层级保护；配置不会直接改动左侧运行菜单
- 字典管理：左侧类型与右侧数据项联动，支持筛选、增改、删除及分页
- 系统日志：操作日志和登录日志双标签，支持筛选、查看和 CSV 导出；登录记录仅来自唯一登录页实际发生的演示事件
- 综合统计：趋势、分布、导出入口
- 用户与组织、栏目、敏感规则、整改台账、系统日志与系统设置入口
- 领导视图：与工作总览平级，包含领导驾驶舱、专题统计、重点事项和公开成果；平台管理员菜单入口与顶部“领导查看”角色共用同一套只读页面和实时业务数据
- 桌面端管理工作台布局（管理端不提供移动端视图）

## 原型约定

角色切换位于右上角，用于演示五类工作视图，不代表真实授权。帖子审核、事项登记分办、承办接收与转办、承办进展与答复、复核反馈、回音壁选择发布、评论举报、注册审核、公告、政策问答、整改及内容配置写入浏览器本地演示数据；刷新仍保留，同源职工端仅展示状态为“已发布”的公开结果，撤回后同步移除。内容公开和事项办理使用两条独立状态线：敏感词命中只影响内容公开与人工复核，建言献策和心声诉求仍进入事项办理候选。分办管理员继续保留独立“整改台账”，栏目管理和敏感词库继续位于配置管理。系统设置数据仍为浏览器演示数据，登录日志不推断 IP、浏览器或设备信息；CSV 可导出当前筛选结果，但安全运维与真实组织隔离尚无后端处理。实际系统需由服务端执行栏目、敏感词、角色、操作及数据范围校验，并保存不可篡改审计记录。

承办演示账号均使用密码 `123456`：`handler`（陈凯，经济发展处）、`handler-office`（刘敏，办公室）、`handler-cooperation`（周磊，合作指导处）。

承办页面的附件输入只保存演示文件名，不上传文件内容；历史事项缺少受理或办结日期时，平均办理时长显示“未统计”。
