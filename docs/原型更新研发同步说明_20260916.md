## 今日原型实际页面清单

### 职工端 Web

- 登录页支持职工端/管理端切换、账号密码登录/短信验证码登录、账号申请与审核查询、忘记密码；“职工移动端”入口进入独立移动登录界面。
- 职工端侧栏顺序为：首页、供销心声、政策答疑与公开、通知公告、个人中心；顶部提供全局搜索和个人菜单。
- 首页当前包含 5 条轮播内容、首页内容三 Tab（全部/精华贴/本周热议）、内容动态、“通知公告”和“我的进度”两个工作区。
- 个人中心桌面端实际为“我的发言 / 收藏 / 互动”三个 Tab；账号设置通过“编辑资料”弹窗进入，弹窗内展示只读姓名、部门、脱敏电话，以及匿名发言和修改密码入口。

### 职工端移动端

- “政策”页实际包含热门政策（支持查看更多）、政策解读/常见问答/整改公开、搜索；常见问答页底部提供“我要提问”和“我的提问”，后者显示数量角标。
- “我的”页实际提供编辑资料、办理进度、我的发言、收藏、互动和退出登录；进入上述子页面后使用顶部返回栏，不显示底部主导航。
- 移动发帖编辑器实际支持栏目、标题、副标题、富文本正文、附件、实名/匿名、允许评论；驳回帖子可从进度详情进入重新提交。

### 管理端

- 平台管理员当前一级菜单为：工作总览、领导视图、数据分析、内容管理、事项办理、审核管理、配置管理、系统设置。
- 内容管理下有：信息台账管理、通知公告管理、政策与问答、轮播图管理、回音壁发布。
- 事项办理下有：信息内容审核、事项分办、公开与归档；审核管理下有：用户审核、评论审核、举报核查。
- 配置管理下有：栏目管理、敏感词库、流程配置、基础配置；系统设置下有：用户管理、组织架构、角色管理、菜单管理、字典管理、系统日志。
- 承办角色使用承办工作台、我的待办、事项办理、答复草稿、催办提醒、已公开答复、部门统计等页面；领导角色只读查看领导驾驶舱、专题统计、重点事项和公开成果。

- 移动端使用底部“首页 / 心声 / 政策 / 公告 / 我的”导航；首页只保留欢迎区、政策 Banner、内容分类和内容流。

- 平台管理员新增/完善：审核管理、系统设置、配置管理、领导视图；系统设置包含用户、组织架构、角色、菜单、字典、系统日志等页面。

## 二、研发必须遵守的业务规则

### 1. 内容公开线与事项办理线分离

帖子是否公开、是否进入事项办理是两个独立决定，不能用一个 `post.status` 同时表达。

建议至少拆分为：

- **内容状态 `contentStatus`：** `待审核`、`已公开`、`未公开办理`、`退回修改`、`驳回`、`已隐藏`。
- **办理状态 `affairStatus`：** `未立项`、`待认领`、`办理中`、`待复核`、`已反馈`、`已办结`。
- **公开范围 `visibility`：** `公开`、`仅本人`、`内部办理`。

建言献策、心声诉求经审核后，审核人分别作出公开决定和办理决定：

| 审核组合 | 内容结果 | 办理结果 |
| --- | --- | --- |
| 仅公开 | 公开 | 不立项 |
| 仅内部办理 | 仅本人/内部办理 | 登记事项 |
| 公开并办理 | 公开 | 登记事项 |
| 不公开且不办理 | 仅本人或驳回 | 不立项，必须记录原因 |

“仅内部办理”不能进入公共内容流，但作者仍可查看提交记录、办理状态和授权范围内的反馈。

### 2. 发帖、评论、举报规则

- 建言献策、心声诉求、业务交流新提交均进入人工审核；审核前不公开。
- 敏感词和受保护名单命中只作为风险标记和人工审核依据，**普通敏感命中仍需提交成功并进入待审核**；不得在客户端直接拦截、丢弃或写入公开内容。
- 若业务确需禁止接收某类内容，应另行配置“禁止提交”规则，不能把普通敏感词规则当作禁止提交规则。
- 评论未命中规则可直接公开；命中敏感规则或受保护名单时提交成功、状态为待审核，审核前不显示在评论区。
- 帖子关闭“允许评论”后，评论入口不可操作；服务端仍需再次校验，不能只依赖前端开关。
- 举报始终进入指定角色人工核查，必须记录成立/不成立及理由；举报成立后由人工选择隐藏、恢复等处置，不自动删除原帖。
- 回音壁是管理端公开答复栏目，职工不能直接发帖。

### 2.1 当前原型展示的职工发言状态

当前原型把帖子和事项合并成职工可读的单条进度标签，展示文案如下；正式开发仍应按“内容状态 + 办理状态 + 公开范围”分字段保存：

| 原型展示 | 使用场景 | 可见性/后续动作 |
| --- | --- | --- |
| 待审核 · 仅个人可见 | 新提交或等待审核 | 作者可查看，不能进入公共内容流 |
| 已驳回 · 仅个人可见 | 审核驳回、退回修改 | 作者可修改后重新提交 |
| 办理中 · 仅个人可见 | 已登记且承办处理中 | 作者查看进度和时间线 |
| 逾期 · 仅个人可见 | 超过当前办理期限 | 由期限动态计算，不自动办结 |
| 已处理-分办审核 · 仅个人可见 | 承办答复已提交、等待复核 | 复核后选择公开答复或私密回复 |
| 已办结 · 公开可见 | 公开答复已发布 | 可进入回音壁/公开内容流 |
| 已办结 · 仅个人可见 | 私密回复已反馈 | 仅作者查看 |
| 审核通过 · 已公开 | 业务交流审核通过 | 进入公开内容流，不生成办理事项 |

### 3. 事项办理与承办流转

标准主流程：

`待登记 → 待承办确认 → 办理中 → 待复核 → 已反馈 → 已办结`

转办支线：

`办理中 → 转办待接收 → 办理中`

退回复核：

`待复核 → 退回修改 → 办理中`

具体规则：

- 建言献策、心声诉求不会因敏感命中而退出办理候选；是否办理由人工审核决定。
- 登记事项时指定初始承办部门和承办人，进入“待承办确认”；初始承办人点击“确认办理”后才进入“办理中”。
- 未确认接收的承办人不得更新进度、保存答复草稿、申请延期或提交正式答复。
- 只有当前最终承办人可以更新进度、编辑答复和提交正式答复；协办部门只提交协同意见和附件。
- 当前承办人发起转办后，原责任人仍保留责任；目标承办人点击“接收办理”后，责任部门和责任人正式变更。
- 转办拒绝、接收人不可用、超时、无人认领等异常必须有退回路径、提醒对象和操作留痕，不能自动办结或自动公开。
- 承办答复提交后进入“待复核”；复核人只能选择“公开答复”或“私密回复”。私密回复只对作者可见，不进入公开内容流。
- 公开答复需经过答复复核和发布动作后，才生成回音壁公开记录；原帖是否公开不能自动推断答复是否公开。

### 4. 流程配置与版本

**当前原型实际表现：**

- “流程配置”页面展示 5 条业务流程：建言献策（`SUGGESTION`）、心声诉求（`APPEAL`）、业务交流（`EXCHANGE`）、评论提交（`COMMENT`）、举报提交（`REPORT`）。
- 列表字段为流程名称、流程编码、基础环节、配置状态、更新时间和操作；当前建言献策/心声诉求显示 2 个固定环节，其他三类显示 1 个固定环节。
- 点击“配置详情”进入弹窗，可查看/编辑审批环节名称、审批角色、指定用户，支持“添加节点”和“保存配置”；保存后记录配置日志。
- 当前页面没有路径检查、模拟运行、发布新版本、生效时间、分支终点、超时兜底等可操作入口；这些属于后端正式实现需要补齐的目标能力。

**后端目标规则：**

- 流程按触发事件配置独立模板，至少覆盖上述五类事件；模板需保存适用栏目、启停、版本、生效时间、接收角色、公共待办、处理节点、分支、复核角色、办理时限、转办范围和超时兜底。
- 模板发布前必须经过“路径检查 → 模拟运行 → 发布”；校验事件匹配唯一、节点可达、分支有终点、退回去向有效、责任角色有数据范围、超时兜底完整。
- 发布产生不可改写的新版本；新触发事件使用生效版本，已发起任务固定使用启动时版本。停用前必须配置替代模板或默认路径，不能影响已运行任务。

### 5. 权限、匿名与审计

- 平台管理员负责模板、栏目、敏感词及全量治理；内容管理员、分办管理员、承办角色只能操作授权节点；领导视图只读。
- 数据权限至少区分全部、本部门、本部门及以下、仅本人等范围，服务端强制校验。
- 匿名只影响展示身份，不等于无身份。匿名作者真实身份只允许具备独立溯源权限的人员在登记理由后查看。
- 认领、转办申请/确认、内容审核、办理决定、答复复核、举报结论、隐藏/恢复、配置发布均记录：操作者、时间、理由、前后状态、模板版本、关联帖子/事项编号。
- 普通流程日志不得直接暴露匿名作者真实身份；审计日志必须不可篡改，并支持按当前筛选条件导出。

## 三、数据与指标口径

### 1. 帖子互动

- 浏览同时记录 PV 和 UV；台账列表展示 PV，详情展示 PV、UV 和趋势。
- 点赞、收藏保留用户级行为记录，取消操作需同步扣减并移除本人记录。
- 评论按已发布、待审核、已驳回、已隐藏分类统计。
- 分享只记录入口和次数（复制链接、站内分享、系统分享等），不记录接收人。
- 互动率：`(点赞数 + 已发布评论数 + 收藏数 + 分享数) / UV`；UV 为 0 时显示 0%。
- 平台管理员可查看点赞/收藏用户级记录；内容管理员只看汇总和匿名化结果。

### 2. 公开内容过滤

职工端首页、供销心声、搜索、移动端内容流只返回满足以下条件的记录：

`contentStatus = 已公开` 且 `enabled != false` 且 `deleted != true` 且未撤回。

待审核、退回修改、驳回、已隐藏、私密回复不得进入公共内容流；作者自己的记录可在个人中心按权限查询。

## 四、研发接口/表结构落地清单

1. **帖子与内容审核：** 帖子、评论、举报、审核记录分表或明确关联；支持内容状态、公开范围、风险命中、作者身份模式、评论开关、附件元数据。
2. **事项办理：** 事项与来源帖子双向关联；保存流程版本快照、当前责任部门/人员、初始责任、转办记录、协办意见、节点事件、期限和超时状态。
3. **流程模板：** 模板草稿、已发布版本、节点、分支、角色范围、超时策略、模拟记录分离存储；运行任务必须绑定 `flowVersionId`。
4. **栏目和敏感词：** 栏目启停影响新发帖选择，不影响历史可见性；敏感词按作用范围匹配，服务端不区分大小写并保留命中记录。
5. **组织与权限：** 组织使用 `parentId + sort` 维护树；删除仅限未被账户或事项引用的叶节点；角色权限与数据范围独立配置。
6. **通知与消息：** 账号审核、退回/驳回、事项接收、转办、答复复核和结果反馈均需形成站内通知；作者只能收到自己有权查看的事项信息。
7. **文件服务：** 附件需独立文件 ID、原名、大小、MIME、病毒/安全扫描状态、访问权限和下载审计；原型中的本地文件名不能直接作为正式实现。

## 五、测试重点与验收清单

- 新发三类帖子均为待审核；待审核帖在作者个人中心可见，在所有公共入口不可见；审核通过后才公开。
- 敏感命中帖/评论可以提交并进入待审核，输入内容和风险命中保留；审核前不公开。
- 建言献策、心声诉求分别验证四种公开/办理组合，确认内容状态和事项状态互不覆盖。
- 验证待承办确认、接收、转办待接收、接收确认、退回修改、延期、待复核、公开答复、私密回复全链路。
- 被驳回帖子可修改后重新提交，重新进入初始审核状态；原审核记录不可覆盖。
- 关闭评论后，Web、移动端和服务端均禁止新评论；已有评论按原状态保留。
- 匿名帖子在普通列表、互动统计和流程日志中不泄露实名；具备审计权限时可按理由溯源。
- 组织、栏目、敏感词、流程模板的写操作均有权限校验和审计；停用模板不影响已运行任务。
- 领导视图只读；承办负责人看不到无数据权限的其他部门事项；平台管理员和承办视图的同一事项数据一致。
- 移动端验证登录、底部导航、详情返回、弹层关闭、图片/附件、提问、进度详情和窄屏无横向溢出。

## 六、原型与正式开发的边界

- 原型中的角色入口、演示账号、浏览器本地存储和权限切换仅用于演示，不代表真实认证、授权、人事组织同步或数据隔离。
- 当前“配置管理 → 流程配置”页面是独立演示配置，尚未接管职工提交、内容审核和事项运行逻辑；正式开发需按本文第二节规则接入服务端流程引擎或等价实现。
- 当前原型的历史演示数据可能同时存在旧状态（如“私密发布”“已处理-分办审核”）；迁移时不得删除帖子、事项、互动和审计记录，应映射到新的内容状态/办理状态字段。
- 本文与《管理端原型设计/流程配置业务需求.md》共同作为后端规则依据；若视觉交互与业务规则冲突，以业务规则和服务端状态机为准。

### 联调前必须确认的一项规则

旧版《流程配置业务需求.md》曾定义：业务交流未命中启用敏感规则时可直接公开，命中后进入人工审核；本轮最新原型和《职工帖子人工审核设计》已改为三类职工发帖统一进入人工审核，当前代码也是统一保存为 `待审核`。研发建表、接口和测试用例应先由产品确认最终口径；在确认前不要为业务交流单独实现自动公开分支。
