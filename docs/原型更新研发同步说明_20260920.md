# 湖北供销职工交流平台

## 原型更新研发同步说明

**更新时间：** 2026-09-20  
**同步对象：** 产品、前端、后端、测试  
**原型入口：** `原型优化设计/index.html`；管理端入口为登录页的“管理视图 / 承办视图 / 领导视图”

> 本文以 2026-09-20 当前可运行原型和代码为准，不只依据已有 Markdown。原型使用浏览器本地数据，角色切换不等于真实权限；正式系统必须由服务端执行认证、授权、数据范围、状态流转和审计校验。

## 一、本轮更新结论

本轮在 9 月 16 日版本基础上，重点完成管理端业务闭环调整：

1. 内容审核与事项分办拆开；建言献策、心声诉求审核通过后自动生成待分办事项。
2. 事项分办统一为“待分办 / 已分办 / 答复审核 / 已办结”四个页签。
3. 分办后直接进入办理中，取消承办确认、目标承办人接收等中间状态。
4. 承办管理收敛为“工作台与任务 / 办理反馈 / 已办结事项”，办理反馈改为三栏工作区。
5. 内容管理只负责已审核内容和运营内容，不再重复内容审核、事项办理或承办动作。
6. 新增匿名内容溯源申请、独立审核、限时限次查看和查看审计。
7. 领导视图和平台工作总览改为基于业务数据的只读统计和闭环监控。
8. 敏感词增加分类、风险等级和分级处置；内容审核增加“待审核 / 风险待审 / 已处理”。

## 三、核心状态模型

帖子必须拆分保存三类状态，不能继续只依赖一个 `status`：

| 字段 | 当前原型值 | 说明 |
| --- | --- | --- |
| `contentAuditStatus` | 待审核、审核通过、已驳回 | 内容合规审核结果 |
| `publishStatus` | 未发布、已发布、私密发布 | 职工端可见范围和发布结果 |
| `handlingStatus` | 不适用、待分办、办理中、待答复审核、退回修改、已办结 | 事项办理进度 |

原型仍兼容旧 `status` 字段和部分历史数据。正式接口应以三类独立状态为准，迁移时做映射，不得覆盖历史审核、办理和发布记录。

### 职工端展示状态

职工端可以把多字段合并成可读标签，但后端仍需分字段保存：

| 展示状态 | 实际含义 |
| --- | --- |
| 待审核 · 仅个人可见 | 内容未完成审核，不进入公共内容流 |
| 已驳回 · 仅个人可见 | 可修改后重新提交，旧审核记录保留 |
| 待分办 / 办理中 · 仅个人可见 | 已生成事项，等待分办或正在办理 |
| 待答复审核 · 仅个人可见 | 承办人已提交正式答复 |
| 退回修改 · 仅个人可见 | 答复审核退回承办人修改 |
| 已办结 · 公开可见 | 公开答复已生成回音壁内容 |
| 已办结 · 仅个人可见 | 私密回复只反馈给发帖人 |
| 审核通过 · 已公开 | 业务交流直接进入公共内容流，不生成事项 |

临期、逾期由办理期限动态计算，是时限标签或筛选条件，不是流程状态。

## 四、发帖、评论与风险规则

### 1. 发帖路由

| 内容类型 | 无规则命中 | 中/低风险或受保护名单命中 | 高风险命中 | 是否生成事项 |
| --- | --- | --- | --- | --- |
| 建言献策 | 进入人工审核 | 进入人工审核，中风险优先 | 阻止提交，提示修改 | 审核通过后自动生成 |
| 心声诉求 | 进入人工审核 | 进入人工审核，中风险优先 | 阻止提交，提示修改 | 审核通过后自动生成 |
| 业务交流 | 直接发布 | 进入人工审核，中风险优先 | 阻止提交，提示修改 | 不生成 |

- 待审核内容只对作者可见，不得出现在首页、供销心声、搜索或移动端公共内容流。
- 审核驳回后允许修改并重新提交；原提交版本和审核记录不得被覆盖。
- 回音壁只接受答复审核生成的公开答复，职工不能在回音壁发帖。
- 栏目停用后不能新发帖，但不影响历史内容按原权限查询。

### 2. 敏感词分级

- 分类包括：信息安全、内部信息、廉洁合规、不文明用语、广告引流、其他。
- 风险等级：高、中、低。
- 高风险：当前原型在发帖和评论提交时直接阻止，记录规则命中次数，但不创建内容记录。
- 中风险：提交成功并进入优先人工审核。
- 低风险：提交成功并进入普通人工审核。
- 受保护名单命中：进入人工复核，不能自动判定违规。
- 匹配方式支持包含匹配和完整词匹配；适用范围支持发帖、评论、全部。
- 信息内容审核中的机器建议和风险预警只提供证据，最终通过或驳回仍由审核人员决定。

### 3. 评论与举报

- 评论未命中规则时直接发布；中低风险或受保护名单命中时进入待审核；高风险阻止提交。
- 帖子关闭评论后，前端入口和服务端接口都必须拒绝新评论。
- 举报按原因类型进入人工核查；核查结论、处置理由、隐藏或恢复动作必须留痕，不能自动删除原帖。

## 五、内容审核与自动成单

信息内容审核页按“待审核 / 风险待审 / 已处理”组织队列，并支持内容分类、风险等级、发布状态和提交时间查询。

审核职责分为两个决定：

1. 内容是否通过审核。
2. 审核通过后采用已发布、私密发布或暂不发布。

流转规则：

- 建言献策、心声诉求审核通过后，立即生成唯一事项编号和待分办事项。
- 业务交流审核通过后进入待发布或已发布路径，不生成事项。
- 内容发布状态和事项状态相互独立；内容隐藏、私密发布不得删除或终止已生成事项。
- 审核动作保存审核人、审核意见、风险证据、处理时间和前后状态。

## 六、事项分办与办理规则

### 1. 主流程

`内容审核通过并自动成单 → 待分办 → 办理中 → 待答复审核 → 已办结`

退回支线：

`待答复审核 → 退回修改 → 办理中 → 再次提交答复审核`

转办支线：

`办理中 → 提交转办申请 → 分办管理员审核并改派 → 新办理人直接办理中`

当前流程不再使用“待承办确认”和“转办待接收”。分办或改派成功后直接变更责任人并进入办理中。

### 2. 事项分办页面

固定四个页签：

- 待分办：查看来源内容并设置主办部门、办理人、协办部门、优先级、期限、要求和反馈方式。
- 已分办：查看当前办理状态、人员、期限和轨迹，可执行催办。
- 答复审核：审核承办人提交的正式答复，可通过或退回修改。
- 已办结：查询最终答复方式、办结时间和完整流转记录。

四个页签统一字段：事项名称/编号、类型、承办部门/办理人、优先级、办理期限、当前状态、节点时间、操作。查询条件按页签复用，待分办时部门和办理人尚未确定，因此对应筛选禁用。

### 3. 分办校验

- 主办部门、当前办理人、办理期限、办理要求、反馈方式为正式分办数据。
- 办理人必须属于主办部门且账号有效。
- 分办成功后写入分办人、分办时间、责任信息快照，并向承办人生成任务通知。
- 只有当前办理人可以更新进展、保存草稿、申请延期、申请转办和提交答复。
- 协办部门只提交协同意见或附件，不取得主办责任。

### 4. 答复审核与办结

- 承办人提交正式答复后进入待答复审核，承办端只读，不能自行撤回或办结。
- 退回时必须填写意见；事项回到退回修改，承办人修改后再次提交。
- 通过时选择公开答复或私密回复，并完成办结。
- 公开答复自动生成回音壁记录；私密回复只对原作者可见，不进入公共内容流。

## 七、承办管理

### 1. 工作台与任务

- 负责发现、筛选和确定优先级，展示待办、临期、催办、退回和已办结指标。
- 任务表格支持业务类型、时限状态、编号或标题查询。
- “办理”进入办理反馈并自动选中同一事项；两个页面使用同一条事项记录，不复制台账。
- 右侧消息提醒聚合新任务、催办、逾期、退回、审核和公开通知。

### 2. 办理反馈

页面为三栏工作区：左侧办理队列、中间单事项办理表单、右侧分办要求/附件/流转记录。

固定状态页签：

- 待处理：已分办但尚无进展、草稿或退回意见。
- 办理中：已有进展或草稿。
- 退回修改：存在答复审核退回意见。
- 已提交：正式答复已提交，映射事项“待复核”，只读。

临期和逾期只作为队列下拉筛选，不设置为状态页签。可编辑事项支持阶段、进展、附件、答复草稿、延期、转办和提交答复审核。

### 3. 已办结事项

- 只展示建言献策和心声诉求的已反馈/已办结事项。
- 支持按关键词、事项类型、承办部门、答复方式和办结时间查询。
- 汇总公开答复、私密回复和按期办结情况，详情只读。

## 八、内容管理边界

- 信息台账管理：只查询审核通过的职工帖子和已办结公开答复；展示发布状态和事项状态，不允许直接修改已审核正文。
- 通知公告管理：状态为草稿、待发布、已发布、已撤回；记录发布范围和触达结果。
- 政策与问答：政策使用草稿、待发布、已发布、已撤回；问题答复使用待答复、答复中、已发布。
- 轮播图管理：只能关联当前有效的帖子、公告、政策、问答或外链；关联内容失效时标记“关联失效”，不能继续启用。
- 回音壁管理：只管理答复审核产生的公开答复；没有手工“新增发布”入口，只支持查看、撤回和恢复。

职工端公共内容查询必须满足：审核通过、发布状态为已发布、未删除、未隐藏、未撤回且栏目有效。

## 九、匿名溯源

### 1. 申请端

- 溯源查询只展示当前登录人的申请。
- 申请必须选择可验证身份绑定的匿名帖子，并填写不少于 10 个字的查询事由。
- 无 `authorId` 或 `authorId` 无法关联有效账号时，不允许申请或批准。
- 申请状态包括待审核、可查看、已过期、已用完、已驳回、身份数据不可用。

### 2. 审核端

- 溯源查询审核是独立权限，按最小必要原则核验申请人、目标帖子和查询事由。
- 申请人不能审核自己的申请。
- 批准范围仅限申请对应的单条帖子，只展示作者真实姓名和所属部门。
- 授权有效期为 24 小时，最多查看 1 次；过期或用完后不得再次返回身份数据。
- 审核决定和实际查看身份是两条独立审计记录，均保存操作者、时间、申请编号、帖子编号和结果。
- 普通内容、事项、互动和流程日志不得泄露匿名作者真实身份。

## 十、工作总览与领导视图

### 1. 平台工作总览

当前展示今日需要关注、发帖量、待审核、待分办、办理中、逾期事项、满意度、近 7 日趋势、业务闭环健康度、优先处理队列和近期运营动态。

- 指标必须由帖子、事项、答复和评价数据计算，不保存重复汇总状态。
- 优先队列按逾期、临期和流程节点排序。
- 满意度只统计办结后的有效评价。
- 导出日报必须沿用当前筛选范围和数据权限。

### 2. 领导视图

- 页面包括领导驾驶舱、专题统计、重点事项、公开成果。
- 驾驶舱展示职工参与率、有效建议、采纳率、跨部门协同、按期办结率、满意度、热点排行、办理转化和重点问题摘要。
- 专题统计支持周期、栏目和组织范围筛选，并提供报告生成和导出。
- 重点事项和公开成果只允许查看和导出，不允许审核、分办、催办、退回、发布、编辑或配置。
- 所有统计受授权组织数据范围约束，前端只读不能替代服务端权限校验。

## 十一、接口与数据落地清单

1. 帖子、内容审核、发布记录、评论、举报分表或保持明确关联，支持风险命中和审核版本。
2. 事项与来源帖子双向关联，保存当前责任、初始责任、分办/改派、期限、进展、答复、反馈方式和完整事件流。
3. 审核通过自动成单必须保证幂等；同一帖子不能重复生成事项。
4. 分办、改派、答复提交、退回和通过使用状态前置校验或乐观锁，防止重复处理。
5. 匿名身份与展示昵称分离；溯源授权、查看次数和过期时间由服务端原子校验。
6. 敏感规则保存分类、风险等级、匹配方式、适用范围、启停和命中次数；服务端执行最终匹配。
7. 附件使用独立文件 ID，保存原名、大小、MIME、安全扫描状态、访问权限和下载审计。
8. 所有列表、统计和导出统一执行角色权限和组织数据范围校验。

## 十二、测试验收重点

- 建言献策、心声诉求提交后进入人工审核；通过后只生成一个待分办事项。
- 业务交流无规则命中时直接发布；中低风险命中时进入人工审核；高风险命中时阻止提交。
- 内容审核、发布状态、事项状态可以独立变化，互不覆盖。
- 分办后直接进入办理中，不出现承办确认或目标接收。
- 转办经管理员批准后直接改派，新办理人无需再次接收。
- 办理反馈四个状态互斥；临期、逾期仅作为时限筛选。
- 答复提交后承办端只读；退回后进入退回修改；通过后移入已办结事项。
- 公开答复自动进入回音壁，私密回复不进入任何公共内容流。
- 信息台账不能修改已审核正文；失效轮播不能启用；回音壁无手工新增入口。
- 匿名申请不能自审，授权 24 小时且只能查看一次；审批和查看分别留痕。
- 领导视图严格只读，指标、导出和重点事项均受授权组织范围限制。
- Web 与移动端验证待审核不可公开、驳回重提、评论开关、附件、返回路径和窄屏布局。

## 十三、原型边界与联调确认项

- 原型数据保存在浏览器本地，仅用于演示；正式系统不能依赖前端状态或角色参数完成授权。
- 当前流程配置页仍是演示配置，尚未完全驱动所有运行时分支；后端需实现可发布版本、运行实例绑定和历史版本保留。
- 当前日期、统计数字和演示账号为固定样例，研发应按真实数据和当前登录上下文计算。
- 9 月 16 日说明中的“待承办确认 / 转办待接收”已废止，以本说明的直接办理、管理员改派为准。
- 9 月 16 日说明中的“三类发帖统一人工审核”已被当前原型替换：业务交流无规则命中时直接发布。
- 9 月 16 日说明中的“敏感命中不得阻止提交”已被当前原型替换为分级处置。由于高风险阻止提交会影响证据留存、申诉和合规策略，产品、法务/合规与研发需在联调前确认是否按当前原型正式落地；确认前不要把该规则写死在不可配置代码中。
