# 内容审核决策弹窗统一设计

## 目标

统一审核通过与驳回操作的命名和确认体验，让按钮表达用户动作，让弹窗说明系统结果。

## 设计

- 审核详情主按钮统一命名为“审核通过”。
- 通过确认弹窗继续使用“确认通过”。
- 驳回弹窗使用与通过弹窗相同的审核内容摘要、敏感词标签、意见区和操作结果结构。
- 驳回原因必填，操作结果说明为内容不发布，并将审核结果及原因通知发布人。
- 通过后生成事项的既有业务逻辑保持不变，只从按钮名称中移除该结果描述。

## 验收

- 详情页操作为“驳回 / 审核通过”。
- 驳回确认弹窗与通过确认弹窗视觉结构一致。
- 通过和驳回提交动作仍调用原有 action。
