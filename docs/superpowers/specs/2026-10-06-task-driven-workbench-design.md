# 任务驱动型工作总览设计说明

## 定位

“工作总览”只服务平台管理员日常处理工作，不承担领导查看和运营统计职责。页面必须优先回答：“我现在有多少工作、先处理什么、哪些事项等待较久”。

## 首屏概览

身份卡右侧保留四项实时工作指标：

1. 待我处理：内容审核 + 待处理事项 + 待公开反馈 + 评论审核 + 举报核查 + 用户审核。
2. 处理中事项：已进入办理流程但尚未形成回复的事项。
3. 长时间未回复：状态为待处理或处理中，且在当前状态持续 7 个自然日及以上的事项。
4. 已回复事项：已形成处理结果并回复的事项。

“待我处理”必须与下方待办任务的数量合计一致。“处理中”不计入待我处理，避免重复。

## 待我处理

工作队列改为六类可直接操作的任务：

- 内容审核
- 待处理事项
- 待公开反馈
- 评论审核
- 举报核查
- 用户审核

“处理中事项”从待办队列移除，只在下方风险事项中出现。每类任务提供明确的业务说明、数量和进入按钮。

## 需关注事项

将“事项处理进度”改为“需关注事项”，按当前状态停留时长排序，优先展示等待时间较长的事项，再展示紧急、重点事项。每行补充：

- 当前状态持续天数
- 当前状态起算日期
- 当前状态
- 下一步动作

待处理事项从事项生成时间起算；处理中事项从完成分类或进入处理的时间起算。时间缺失时显示“时长未记录”，不计入“长时间未回复”。删除无实际筛选功能的状态标签页，改为“按处理优先级排序”说明。

## 表达规则

- 删除 `TODAY'S WORK` 和 `ITEMS IN FOCUS` 等英文装饰标题。
- 不在工作总览展示“专题办理量”和“公开内容量”，这些指标归属数据驾驶舱。
- 数据口径用信息图标表达，支持鼠标悬浮和键盘聚焦。
- 顶部指标可点击：待我处理定位到任务队列，其他指标进入事项处理。

## 验收标准

- 待我处理数量等于六类任务数量之和。
- 顶部四项均为日常处理所需数据。
- 任务队列不再包含“处理中事项”。
- 长时间未回复只统计当前状态持续 7 个自然日及以上的待处理、处理中事项。
- 需关注事项每行能看到状态时长、起算日期和下一步动作。
- 工作总览不展示截止日期、逾期天数等当前事项处理流程没有来源的字段。
- 页面不再出现中英文混用的装饰标题。
