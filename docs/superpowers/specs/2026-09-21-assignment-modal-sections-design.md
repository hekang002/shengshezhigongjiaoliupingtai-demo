# 分办弹窗分区设计

## 目标

将“事项流转”与“责任与时限”从同一连续容器中拆开，让流程状态和可编辑表单形成清晰的信息层级。

## 设计决策

- 左侧保留“发帖信息”，不改变来源内容的展示逻辑。
- 弹窗使用三栏结构：左侧事项内容、中间业务处理区、右侧窄版流程栏。待分办时中间区为“分办设置”，其他状态为对应的办理、答复审核或办结详情。
- 流程栏使用系统统一的四个状态节点，按最终节点在上的顺序纵向展示：“已办结 → 答复审核 → 办理中 → 待分办”。“内容审核通过”只作为前置结果，不单独计为节点。
- 责任表单使用独立白色容器和标题描述，所有原有字段、默认值、校验和提交逻辑保持不变。
- 待分办、办理中、答复审核、已办结详情全部复用同一流程栏结构。
- 事项未办结时发布状态必须为“未发布”；答复审核通过并回复用户后，才能进入“已办结”并记录公开答复或私密回复。
- 700px 以下使用单列顺序：事项内容、业务处理区、流程栏。

## 验收标准

- 流程区与表单区有独立背景、边界和间距，不再视为同一表单组。
- 右侧流程栏宽度明显小于中间操作区，四个节点倒序纵向展示，当前状态高亮。
- “确认分办”原有交互和字段校验保持有效。
- 未办结事项的详情不得显示“已发布”，也不得提供提前发布操作。
