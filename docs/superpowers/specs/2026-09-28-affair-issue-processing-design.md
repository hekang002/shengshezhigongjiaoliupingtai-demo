# 事项问题整理与统一回复设计

## 目标

将事项办理定位为管理人员的问题归集、标记、线下研究结论记录和统一回复工具，不建设会议流程，也不设置部门承办。

## 业务流程

1. 内容发布后生成“待处理”事项，事项分类初始为“待分类”。
2. 管理人员执行“标记问题”，设置事项分类、主题标签、重点/共性属性和内部备注。
3. 保存后进入“处理中”，可记录线下讨论结论、保存回复草稿或选择多条事项统一回复。
4. 回复发送后进入“已回复”，回复先通知内容提交人；是否发布到回音壁由独立按钮决定。

## 页面规则

- 来源类型包括建言献策、心声诉求和业务交流。
- 列表删除“回复方式”，保留事项分类、事项属性和阶段时间。
- 待处理操作命名为“标记问题”。
- 处理中操作命名为“记录结论”，批量操作保留“统一回复”。
- 回复弹窗增加“讨论结论”，不展示公开/私密回复方式。
- 已回复详情展示讨论结论、回复内容、回复人、回复时间和回音壁状态。

## 验收

- 新事项不再根据来源栏目自动分类。
- 三类来源内容均可进入事项处理。
- 页面中无承办部门、办理人、办理期限或回复方式字段。
- 讨论结论可以随草稿保存，并随回复记录留痕。
